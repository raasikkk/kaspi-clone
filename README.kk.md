# Kaspi POS Automation

Kaspi Pay API арқылы POS-жүйелер үшін төлемдерді автоматтандыру. Жоба шот-фактуралар жасау, QR-кодтар генерациялау, транзакциялар тарихын қарау, қаржылық статистиканы агрегациялау және қайтаруларды рәсімдеу үшін серверлік қосымша мен веб-интерфейс ұсынады.

## Сәулет

```
┌──────────────┐       ┌──────────────────┐       ┌──────────────────┐
│  Web UI      │◄─────►│  Express Server   │◄─────►│  Kaspi Pay API   │
│  (public/)   │       │  (server.js)      │       │  (entrance/      │
│              │       │                   │       │   mtoken/qrpay)  │
└──────────────┘       └──────────────────┘       └──────────────────┘
                              │
                    ┌─────────┴─────────┐
                    │   src/            │
                    │  ├─ config.js     │  Кілт жұбы, құрылғы, тұрақтылар
                    │  ├─ crypto.js     │  ECDH, ECDSA, TOTP, AES-256-GCM
                    │  ├─ db.js         │  PostgreSQL пулы & схема миграциясы
                    │  ├─ helpers.js    │  Пакеттік fetch, логгер, тақырыптар
                    │  ├─ logger.js     │  Логтарды файлға және консольге жазу
                    │  ├─ polling.js    │  Төлем статустарын резильентті сұрау
                    │  ├─ webhookStore  │  TTL-кэші бар вебхук қоймасы
                    │  ├─ middleware/   │  Ортақ делдалдар (API Auth, Session)
                    │  └─ routes/       │  API маршруттары
                    │     ├─ admin.js   │  API-кілттерді басқару
                    │     ├─ auth.js    │  SMS-авторизация және кассир сессиялары
                    │     ├─ invoice.js │  Шоттарды қашықтан жіберу
                    │     ├─ qr.js      │  Интерактивті QR-код арқылы төлеу
                    │     ├─ history.js │  Kaspi транзакциялар тарихын қарау
                    │     ├─ orders.js  │  Шоттар, статустарды қолмен бақылау
                    │     ├─ refund.js  │  Қайтаруларды рәсімдеу және өткізу
                    │     └─ stats.js   │  Статистика, тізімдер, синхрондау
                    └───────────────────┘
```

Сервер **авторизациядан кейін stateless** — сессия деректері (шифрланған `vtokenSecret`, `tokenSN`, `profileId`) клиент жағында сақталады және қарапайым сұраулар кезінде қорғалған тақырыптар арқылы жіберіледі, немесе қолданылатын `X-API-Key` негізінде деректер базасынан алынады.

## Резильенттілік пен сенімділік

Жүйенің сенімділігін қамтамасыз ету үшін корпоративтік деңгейдегі сәулеттік шешімдер енгізілген:

1. **Резильентті статус сұрау (Degraded Polling Mode)**:
   Kaspi API уақытша қолжетімсіз болғанда немесе желіде ақаулар туындағанда, фондық опросчик транзакцияларды бақылауды тоқтатпайды. Оның орнына прогрессивті сұрау күту интервалы қосылады:
   - **1–10 сәтсіз әрекет**: орындалу стандартты жиілікте жалғасады (әр 3 секунд сайын).
   - **11–20 сәтсіз әрекет**: жиілік 1 минутқа дейін төмендейді.
   - **20-дан көп сәтсіз әрекет**: жиілік 5 минутқа дейін төмендейді.
   - **Таймаут (1 сағат)**: егер байланыс 1 сағат бойы қалпына келмесе, бақылау тоқтатылады және төлем `Error` статусына ауыстырылады.
   - **Қалпына келу**: Kaspi-ден алғашқы сәтті жауап алынған кезде опрос интервалдары лезде жылдам режимге (3 секунд) қайтарылады.

2. **Тапсырыстарды қайталаудан қорғау (Duplicate Prevention)**:
   Клиентке бір тапсырыс бойынша қателікпен екінші рет шот жіберуді болдырмау үшін (мысалы, кассир батырманы екі рет басса немесе желіде қайталанулар болса):
   - Деректер базасы деңгейінде `UNIQUE(key_id, order_id)` қатаң шектеуі қойылған.
   - API деңгейінде Kaspi-ге сұрау жібермес бұрын деректер базасы тексеріледі. Егер бұл тапсырысқа бұрын шот жасалған болса, сервер қолданыстағы төлем деректерін бірден қайтарады, осылайша Kaspi API-ге сұрау жіберуді айналып өтіп, тұтынушының Kaspi қосымшасында артық шоттардың пайда болуына жол бермейді.

3. **Авторизация сессияларының қоқыс жинағышы (Auth Cleanup Garbage Collector)**:
   Авторизация процесінде жадтың толып кетуін (`OutOfMemory`) болдырмау үшін, аяқталмаған 3 қадамды SMS-сессиялар 15 минуттан кейін қоқыс жинағыш арқылы автоматты түрде жадтан өшіріледі.

## Webhooks (Вебхуктар)

Сервер жасалған QR және invoice төлемдерінің статустарын автоматты түрде бақылайды және статус өзгерген кезде тіркелген URL мекенжайларына HTTP POST хабарламаларын жібереді.

- 📡 **Оқиғалар**: `payment.success` (төлем сәтті өтті) · `payment.failed` (ақаулық/бас тарту) · `payment.expired` (күту уақыты бітті).
- 📝 **Триггерлер**: Вебхуктар фондық опросчик арқылы статус автоматты түрде жаңарғанда да, `PATCH /api/orders/:id/status` арқылы статус қолмен өзгертілгенде де жіберіледі.
- ⚙️ **Конфигурация**: дискілік жүктемені азайту үшін 5 секундтық TTL-кэші бар `webhooks.json` файлы арқылы бапталады.
- 🔐 **Қауіпсіздік**: хабарламалар `X-Webhook-Signature` тақырыбында HMAC SHA-256 қолтаңбасымен қол қойылады.
- 🔄 **Retry логикасы**: жеткізу сәтсіз аяқталған жағдайда, қайталау әрекеттері экспоненциалды кідіріспен автоматты түрде орындалады (3 әрекет: 5 сек, 30 сек кейін, сосын бас тартылады). Қайталау кезегі сервер қайта іске қосылғанда жойылмауы үшін дискіге сақталады.

> 📖 Толығырақ — [API құжаттамасында](./docs/API.kk.md#webhooks--хабарламалар).

## Жылдам бастау

### Локалды іске қосу

```bash
# 1. Репозиторийді клондау
git clone https://github.com/tapter-dev/kaspi-pos-automation.git
cd kaspi-pos-automation

# 2. Тәуелділіктерді орнату
npm install

# 3. Орта айнымалыларын баптау
# .env.example негізінде .env файлын жасаңыз
cp .env.example .env
# TOKEN_SECRET_KEY кілтін генерациялап жазыңыз, DATABASE_URL айнымалысына PostgreSQL қосылу сілтемесін баптаңыз

# 4. Вебхуктарды баптау (қосымша)
cp webhooks.example.json webhooks.json

# 5. Серверді іске қосу
npm start
```

Бірінші іске қосу кезінде қосымша автоматты түрде қажетті файлдарды (`keypair.json`, `device.json`) жасайды және PostgreSQL кесте миграцияларын қолданады.

### Docker Compose арқылы іске қосу

Қосымша мен PostgreSQL деректер базасын контейнерлерде дайын күйде өрістету үшін:

```bash
# Контейнерлерді құрастыру және фонда іске қосу
docker compose up --build -d
```

Қосымша хост-машинаның `3000` портында, ал PostgreSQL `5434` портында қолжетімді болады.

| ------------------ | ---------------------------------------------------------------------- | ------------ | -------- |
| `TOKEN_SECRET_KEY` | Сессияларды AES-256-GCM шифрлау үшін 64 символды hex-кілт (32 байт)    | —            | **Иә**   |
| `DATABASE_URL`     | PostgreSQL қосылу сілтемесі                                            | —            | **Иә**   |

| `APP_PLATFORM`     | Платформа (`iOS` немесе `Android`)                                     | `iOS`        | Жоқ      |

## Кілттерді ротациялау

Егер құрылғы немесе кілттер қауіпсіздігі бұзылса, оларды қауіпсіз түрде қайта генерациялауға болады:

```bash
npm run regen:keypair   # Авторизацияның ECDSA кілттерін ротациялау
npm run regen:device    # Құрылғының UUID идентификаторларын ротациялау
```

Қайта іске қосылғаннан кейін қолданыстағы кассир сессиялары мәжбүрлі түрде жойылады, ал ескі файлдар резервтік `.bak` көшірмелері ретінде сақталады.

## Демо-интерфейс (`public/`)

Сервер `http://localhost:3000` мекенжайы бойынша қолжетімді кірістірілген демонстрациялық SPA-интерфейсін ұсынады.

- 🔐 **Авторизация**: Кассирдің телефон нөмірін енгізу $\rightarrow$ SMS OTP-кодты енгізу $\rightarrow$ кассир профилін сақтау және оны деректер базасындағы API-кілтіңізге автоматты түрде байланыстыру.
- 🧾 **Шоттар мен QR-кодтар**: Тұтынушыларға таймерлердің кері санағы және нақты уақыттағы статусы бар шоттар жасау.
- 📊 **Статистика кабинеті**: Іс-шаралар бойынша агрегацияланған қаржылық көрсеткіштер, тапсырыстар тізімдері және статустарды мәжбүрлі синхрондау.
