# Kaspi POS Automation

Автоматизация платежей для POS-систем через Kaspi Pay API. Проект предоставляет серверное приложение и веб-интерфейс для создания счетов, генерации QR-кодов, просмотра истории транзакций, агрегации финансовой статистики и оформления возвратов.

## Архитектура

```
┌──────────────┐       ┌──────────────────┐       ┌──────────────────┐
│  Web UI      │◄─────►│  Express Server   │◄─────►│  Kaspi Pay API   │
│  (public/)   │       │  (server.js)      │       │  (entrance/      │
│              │       │                   │       │   mtoken/qrpay)  │
└──────────────┘       └──────────────────┘       └──────────────────┘
                              │
                    ┌─────────┴─────────┐
                    │   src/            │
                    │  ├─ config.js     │  Ключ-пара, устройство, константы
                    │  ├─ crypto.js     │  ECDH, ECDSA, TOTP, AES-256-GCM
                    │  ├─ db.js         │  PostgreSQL пул & миграции схем
                    │  ├─ helpers.js    │  Пакетный fetch, логгер, заголовки
                    │  ├─ logger.js     │  Запись логов в файл и консоль
                    │  ├─ polling.js    │  Резильентный опрос статуса платежей
                    │  ├─ webhookStore  │  Хранилище вебхуков с TTL-кэшем
                    │  ├─ middleware/   │  Общие посредники (API Auth, Session)
                    │  └─ routes/       │  Маршруты API
                    │     ├─ admin.js   │  Управление API-ключами
                    │     ├─ auth.js    │  SMS-авторизация и сессии кассиров
                    │     ├─ invoice.js │  Удаленное выставление счетов
                    │     ├─ qr.js      │  Интерактивная оплата по QR-коду
                    │     ├─ history.js │  Просмотр истории транзакций Kaspi
                    │     ├─ orders.js  │  Счета, ручной контроль статусов
                    │     ├─ refund.js  │  Оформление и проведение возвратов
                    │     └─ stats.js   │  Статистика, списки, синхронизация
                    └───────────────────┘
```

Сервер является **stateless после авторизации** — данные сессии (зашифрованный `vtokenSecret`, `tokenSN`, `profileId`) хранятся на стороне клиента и передаются через защищенные заголовки при обычных запросах, либо извлекаются из базы данных на основе используемого `X-API-Key`.

## Резильентность и надежность

В систему заложены архитектурные решения корпоративного уровня для обеспечения надежности:

1. **Резильентный опрос статусов (Degraded Polling Mode)**:
   При возникновении временных сетевых сбоев или перегрузки Kaspi API фоновый опросчик не отбрасывает транзакции. Вместо этого включается прогрессивный интервал задержки опроса:
   - **1–10 сбоев**: опрос продолжается на стандартной частоте (каждые 3 секунды).
   - **11–20 сбоев**: частота снижается до 1 минуты.
   - **Более 20 сбоев**: частота снижается до 5 минут.
   - **Таймаут (1 час)**: если связь не восстанавливается в течение 1 часа, отслеживание прекращается, и платеж переводится в статус `Error`.
   - **Восстановление**: при первом успешном ответе от Kaspi интервалы мгновенно сбрасываются в быстрый режим (3 секунды).

2. **Защита от дублирования заказов (Duplicate Prevention)**:
   Для предотвращения ошибочного выставления повторных счетов (например, при двойном клике кассира или сетевых повторах):
   - На уровне базы данных наложено строгое ограничение `UNIQUE(key_id, order_id)`.
   - На уровне API перед отправкой запроса в Kaspi проверяется база данных. Если счет для данного заказа уже создавался, сервер возвращает существующие реквизиты оплаты напрямую, полностью минуя вызов Kaspi API и предотвращая создание лишних счетов в приложении клиента.

3. **Сборщик мусора сессий авторизации (Auth Cleanup Garbage Collector)**:
   Для предотвращения утечек памяти (`OutOfMemory`) в процессе авторизации, незавершенные 3-шаговые SMS-сессии автоматически вычищаются из памяти сборщиком мусора, если они не были завершены в течение 15 минут.

## Webhooks (Вебхуки)

Сервер автоматически отслеживает статусы созданных QR- и invoice-платежей и отправляет HTTP POST-уведомления на зарегистрированные URL-адреса при изменении состояний.

- 📡 **События**: `payment.success` (платеж проведен) · `payment.failed` (ошибка/отмена) · `payment.expired` (истекло время ожидания).
- 📝 **Триггеры**: Вебхуки отправляются как при автоматическом обновлении статуса фоновым опросчиком, так и при ручном переопределении статуса через `PATCH /api/orders/:id/status`.
- ⚙️ **Конфигурация**: настраивается через файл `webhooks.json` во временном кэше с TTL в 5 секунд для снижения дисковой нагрузки.
- 🔐 **Безопасность**: сообщения подписываются HMAC SHA-256 подписью в заголовке `X-Webhook-Signature`.
- 🔄 **Retry логика**: при сбое доставки повторные попытки выполняются автоматически с экспоненциальной задержкой (3 попытки: через 5 сек, 30 сек, затем отмена). Очередь повторов сохраняется на диск для выживания при перезапусках.

> 📖 Подробнее — в [документации API](./docs/API.md#webhooks--уведомления).

## Быстрый старт

### Локальный запуск

```bash
# 1. Клонировать репозиторий
git clone https://github.com/tapter-dev/kaspi-pos-automation.git
cd kaspi-pos-automation

# 2. Установить зависимости
npm install

# 3. Настроить переменные окружения
# Создайте файл .env на основе .env.example
cp .env.example .env
# Сгенерируйте и запишите TOKEN_SECRET_KEY, настройте подключение к PostgreSQL в DATABASE_URL

# 4. Настроить вебхуки (опционально)
cp webhooks.example.json webhooks.json

# 5. Запустить сервер
npm start
```

При первом запуске приложение автоматически создаст необходимые файлы (`keypair.json`, `device.json`) и применит PostgreSQL-миграции таблиц.

### Запуск через Docker Compose

Для развертывания готовой связки приложения и базы данных PostgreSQL в контейнерах:

```bash
# Сборка и запуск контейнеров в фоновом режиме
docker compose up --build -d
```

Приложение будет доступно на порту `3000`, а PostgreSQL — на порту `5434` хост-машины.

## Переменные окружения (`.env`)

| Переменная         | Описание                                                                 | По умолчанию | Обязательная |
| ------------------ | ------------------------------------------------------------------------ | ------------ | ------------ |
| `TOKEN_SECRET_KEY` | 64-символьный hex-ключ (32 байта) для AES-256-GCM шифрования сессий      | —            | **Да**       |
| `DATABASE_URL`     | URL подключения к PostgreSQL                                             | —            | **Да**       |
| `ADMIN_SECRET_KEY` | Пароль администратора для эндпоинтов управления ключами (`/api/admin/*`) | —            | **Да**       |
| `PORT`             | Порт веб-сервера                                                         | `3000`       | Нет          |
| `APP_VERSION`      | Версия эмулируемого приложения Kaspi Pay                                 | `4.115`      | Нет          |
| `APP_BUILD`        | Номер сборки Kaspi Pay                                                   | `1115`       | Нет          |
| `APP_PLATFORM`     | Платформа (`iOS` или `Android`)                                          | `iOS`        | Нет          |
| `APP_PLATFORM_VER` | Версия операционной системы                                              | `18.5`       | Нет          |
| `APP_LOCALE`       | Языковой стандарт                                                        | `ru-RU`      | Нет          |
| `APP_MODEL`        | Эмулируемая модель смартфона                                             | `iPhone17,3` | Нет          |

## Ротация ключей

Если устройство или ключи скомпрометированы, вы можете безопасно перегенерировать их:

```bash
npm run regen:keypair   # Ротация ECDSA ключей авторизации
npm run regen:device    # Ротация UUID идентификаторов устройства
```

После перезапуска существующие сессии кассиров будут принудительно аннулированы, старые файлы сохранятся в виде резервных копий `.bak`.

## Демо-интерфейс (`public/`)

Сервер раздает встроенный демонстрационный SPA-интерфейс, доступный по адресу `http://localhost:3000`.

- 🔐 **Авторизация**: Ввод номера телефона кассира $\rightarrow$ ввод SMS OTP-кода $\rightarrow$ сохранение профиля и автоматическая привязка к вашему API-ключу в базе данных.
- 🧾 **Счета и QR-коды**: Создание счетов клиентам с обратным отсчетом таймеров и отображением статуса в реальном времени.
- 📊 **Кабинет статистики**: Детализация агрегированных финансовых показателей за мероприятия, списки заказов и принудительная синхронизация статусов.
