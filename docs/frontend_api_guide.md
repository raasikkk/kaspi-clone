В этом документе собрано полное техническое описание всех **28 эндпоинтов** нашего шлюза автоматизации Kaspi Pay POS. Оно составлено на основе актуального кода бэкенда и спецификации Swagger (`openapi.json`).

## 🔐 Схемы аутентификации и заголовки (Authentication Schemes)

Наш бэкенд использует три различных уровня авторизации в зависимости от вызываемого эндпоинта. Перед отправкой запроса убедитесь, что передаете правильные заголовки:

### 1. Токен доступа Мерчанта (`ApiKeyAuth`)

Основной способ авторизации для большинства клиентских и кассовых операций (создание заказов, генерация QR, просмотр локальной статистики).

- **Заголовок**: `X-API-Key`
- **Формат**: Уникальная строка, генерируемая для каждого мерчанта. Пример: `apipay_org_8f6d2b...`
- **Особенность**: Бэкенд автоматически находит привязанную к этому ключу сессию кассира Kaspi в базе данных и подставляет нужные сессионные токены перед отправкой прокси-запросов к Kaspi Pay. Вы избавлены от необходимости хранить сессию на клиенте!

### 2. Административный токен (`AdminBearerAuth`)

Используется исключительно для управления API-ключами мерчантов (создание, блокировка, удаление).

- **Заголовок**: `Authorization`
- **Формат**: `Bearer <ADMIN_SECRET_KEY>` (секретный ключ администратора из конфигурации бэкенда).

### 3. Низкоуровневые заголовки сессии Kaspi

Используются при прямом проксировании запросов в Kaspi Pay в обход сохраненного API-ключа мерчанта.

- **Заголовки**:
  - `X-Token-SN` — серийный номер токена авторизации Kaspi.
  - `X-Vtoken-Secret` — зашифрованный секрет сессии.
  - `X-Profile-Id` — ID профиля организации в Kaspi (необязательный).
- **Особенность**: Если в запросе отсутствует заголовок `X-API-Key`, но переданы эти заголовки, бэкенд расшифрует сессию напрямую.

### Группа 1: Администрирование и Системные запросы (Admin & System)

Эндпоинты для настройки шлюза, создания API-ключей для новых кинотеатров/мерчантов и базовой проверки жизнедеятельности системы.

#### 1.1 Проверка работоспособности (Health Check)

Простой пинг для мониторинга доступности бэкенда. Не требует авторизации.

- **Метод и путь**: `GET /health`
- **Заголовки**: Не требуются.
- **Ответ (200 OK)**:
  ```json
  {
    "status": "ok"
  }
  ```

#### 1.2 Получить список всех API-ключей

Возвращает список всех зарегистрированных организаций и параметров доступа для административной панели.

- **Метод и путь**: `GET /api/admin/keys`
- **Заголовки**: `Authorization: Bearer <ADMIN_SECRET_KEY>`
- **Ответ (200 OK)**:
  ```json
  [
    {
      "id": 1,
      "theater_name": "Кинотеатр Ала-Тоо",
      "api_key": "apipay_org_8f6d2b...",
      "status": "active", // Возможные статусы: active | suspended
      "allow_invoice": true,
      "allow_qr": true,
      "allow_refund": false,
      "profile_id": "987654",
      "expires_at": "2026-12-31T23:59:59.000Z", // Срок действия ключа (ISO-8601, null если бессрочный)
      "is_connected": true, // Подключен ли кассир к Kaspi (наличие токена в БД)
      "created_at": "2026-06-25T10:00:00.000Z"
    }
  ]
  ```

#### 1.3 Создать новый API-ключ

Регистрирует нового мерчанта/кинотеатр в системе и настраивает его права.

- **Метод и путь**: `POST /api/admin/keys`
- **Заголовки**: `Authorization: Bearer <ADMIN_SECRET_KEY>`
- **Тело запроса (JSON)**:
  ```json
  {
    "name": "Кинотеатр Цезарь", // Обязательно. Название организации
    "allow_invoice": true, // Необязательно (по умолчанию false)
    "allow_qr": true, // Необязательно (по умолчанию true)
    "allow_refund": false, // Необязательно (по умолчанию false)
    "expires_at": "2026-12-31T23:59:59.000Z" // Необязательно. Дата окончания действия ключа (ISO-8601)
  }
  ```
- **Ответ (201 Created)**:
  ```json
  {
    "id": 2,
    "theater_name": "Кинотеатр Цезарь",
    "api_key": "apipay_org_a91f3c...",
    "status": "active",
    "allow_invoice": true,
    "allow_qr": true,
    "allow_refund": false,
    "expires_at": "2026-12-31T23:59:59.000Z",
    "created_at": "2026-06-26T12:00:00.000Z"
  }
  ```

#### 1.4 Обновить параметры API-ключ

Частичное обновление настроек, прав доступа или статуса блокировки ключа.

- **Метод и путь**: `PATCH /api/admin/keys/{id}`
- **Параметры пути**:
  - `id` (integer) — уникальный числовой ID ключа.
- **Заголовки**: `Authorization: Bearer <ADMIN_SECRET_KEY>`
- **Тело запроса (JSON)**:
  ```json
  {
    "name": "Кинотеатр Цезарь Обновленный", // Опционально
    "allow_invoice": true, // Опционально
    "allow_qr": false, // Опционально
    "allow_refund": true, // Опционально
    "status": "suspended", // Опционально. Значения: active | suspended
    "expires_at": "2026-12-31T23:59:59.000Z" // Опционально. Изменить срок действия (передайте null, чтобы сделать бессрочным)
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "id": 2,
    "theater_name": "Кинотеатр Цезарь Обновленный",
    "api_key": "apipay_org_a91f3c...",
    "status": "suspended",
    "allow_invoice": true,
    "allow_qr": false,
    "allow_refund": true,
    "expires_at": "2026-12-31T23:59:59.000Z",
    "is_connected": false,
    "created_at": "2026-06-26T12:00:00.000Z"
  }
  ```

#### 1.5 Отозвать (удалить) API-ключ

Безвозвратное удаление ключа мерчанта из базы данных.

- **Метод и путь**: `DELETE /api/admin/keys/{id}`
- **Параметры пути**:
  - `id` (integer) — числовой ID ключа.
- **Заголовки**: `Authorization: Bearer <ADMIN_SECRET_KEY>`
- **Ответ (200 OK)**:
  ```json
  {
    "success": true,
    "message": "API Key for 'Кинотеатр Цезарь Обновленный' has been deleted."
  }
  ```

### Группа 2: Авторизация в Kaspi (3-step SMS Flow)

Используется для интеграции интерактивного виджета/страницы привязки личного кабинета кассира Kaspi Pay к нашему шлюзу. Процесс идет строго по шагам.

#### 2.1 Инициализация авторизации (Шаг 1)

Инициализирует сессию входа на стороне Kaspi и возвращает ID процесса.

- **Метод и путь**: `POST /api/auth/init`
- **Заголовки**: Не требуются.
- **Ответ (200 OK)**:
  ```json
  {
    "success": true,
    "processId": "proc_uuid_abc123...",
    "view": "EnterPhoneNumber", // Какую страницу показывать на фронте следующим шагом
    "body": { ... } // Сырой ответ от API Kaspi для отладки
  }
  ```

#### 2.2 Отправка номера телефона кассира (Шаг 2)

Отправляет номер телефона кассира для отправки SMS-кода авторизации со стороны Kaspi.

- **Метод и путь**: `POST /api/auth/send-phone`
- **Заголовки**: Не требуются.
- **Тело запроса (JSON)**:
  ```json
  {
    "phoneNumber": "77071234567", // Обязательно. Строка, 11 цифр без знака "+"
    "processId": "proc_uuid_abc123..." // Обязательно. ID процесса из шага 1
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "success": true,
    "processId": "proc_uuid_abc123...",
    "desc": "Код отправлен на номер +7 707 *** ** 67",
    "view": "EnterOtp", // Сигнал фронтенду переключиться на ввод кода
    "body": { ... }
  }
  ```

#### 2.3 Ввод и верификация OTP-кода (Шаг 3)

Отправляет 4-значный код подтверждения из SMS. В случае успеха бэкенд автоматически запрашивает ключи шифрования, выполняет ECDH-согласование ключей, сохраняет токен сессии в базе данных и привязывает его к `X-API-Key`.

- **Метод и путь**: `POST /api/auth/verify-otp`
- **Заголовки**: `X-API-Key: apipay_org_...` (Обязательно, чтобы связать сессию с конкретным мерчантом).
- **Тело запроса (JSON)**:
  ```json
  {
    "otp": "4815", // Обязательно. 4-значная строка из SMS
    "processId": "proc_uuid_abc123..." // Обязательно. ID процесса
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "success": true,
    "processId": "proc_uuid_abc123...",
    "step": "finished",
    "message": "OTP verified and cashier profile linked in database."
  }
  ```

#### 2.4 Обновление токена сессии (Refresh Session via SignInLite)

Используется для продления жизни сессионного токена Kaspi, если он протух (Kaspi сессии требуют регулярного продления).

- **Метод и путь**: `POST /api/auth/refresh`
- **Заголовки**: `X-API-Key` (рекомендуется) или ручные заголовки сессии (`X-Token-SN`, `X-Vtoken-Secret`).
- **Тело запроса (JSON)**:
  ```json
  {
    "tokenSN": "9876543210123456", // Опционально (если передан X-API-Key, подтянется из БД)
    "vtokenSecret": "ENCRYPTED_SECRET...", // Опционально (если передан X-API-Key, подтянется из БД)
    "organizationId": 0 // Опционально. ID организации для переключения контекста
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "success": true,
    "tokenSN": "NEW_TOKEN_SN_1234...",
    "vtokenSecret": "NEW_ENCRYPTED_SECRET...",
    "profileId": "123456",
    "organizationId": 67890,
    "orgName": "ИП ТАПТЕР-ДЕВ",
    "sessionId": "kaspi_session_id_string",
    "organizations": [ ... ], // Список доступных организаций для переключения
    "orgContext": true, // Успешно ли загружен контекст организации
    "message": "Session refreshed via SignInLite + org-context and saved in database."
  }
  ```

#### 2.5 Проверка локального состояния сессии

Позволяет фронтенду быстро проверить, передан ли токен в теле запроса.

- **Метод и путь**: `POST /api/auth/session`
- **Заголовки**: Не требуются.
- **Тело запроса (JSON)**:
  ```json
  {
    "tokenSN": "TOKEN_SN_VALUE" // Строка токена
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "authenticated": true,
    "tokenSN": "TOKEN_SN_VALUE"
  }
  ```

#### 2.6 Выход из системы (Logout)

Уничтожает сессию авторизации на клиенте (сбрасывает контекст).

- **Метод и путь**: `POST /api/auth/logout`
- **Заголовки**: Не требуются.
- **Ответ (200 OK)**:
  ```json
  {
    "success": true
  }
  ```

### Группа 3: Удаленное выставление счетов (Invoicing API)

Интеграция удаленной оплаты по номеру телефона клиента. Клиент получает push-уведомление в приложение Kaspi.kz и оплачивает его там.

#### 3.1 Запрос информации о клиенте перед оплатой

Используется для валидации номера телефона. Возвращает имя и отчество клиента, чтобы кассир мог подтвердить личность плательщика на экране кассы перед выставлением счета.

- **Метод и путь**: `GET /api/invoice/client-info`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Параметры запроса (Query)**:
  - `phoneNumber` (string) — Обязательно. Номер в формате `7XXXXXXXXXX`.
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": {
      "FirstName": "Александр",
      "MiddleName": "Сергеевич",
      "LastName": "П.",
      "HasKaspiGold": true
    }
  }
  ```

#### 3.2 Отправить удаленный счет на оплату

Выставляет счет в приложение клиента.

- **Метод и путь**: `POST /api/invoice/create`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Тело запроса (JSON)**:
  ```json
  {
    "phoneNumber": "77071234567", // Обязательно. Номер плательщика
    "amount": 1000, // Обязательно. Сумма счета в тенге
    "comment": "Оплата заказа #42" // Опционально. До 50 символов (ограничение Kaspi)
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": {
      "Id": 123456, // ID операции в Kaspi для отслеживания статуса
      "Status": "RemotePaymentCreated",
      "Amount": 1000,
      "ClientMobile": "77071234567",
      "ReceiptUrl": "https://pay.kaspi.kz/receipt/...", // Ссылка на будущий чек
      "OrderNumber": "ORDER-12345"
    }
  }
  ```

#### 3.3 Получить статус/детали счета

Опрашивает статус ранее созданного счета.

- **Метод и путь**: `GET /api/invoice/details`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Параметры запроса (Query)**:
  - `operationId` (string) — Обязательно. ID операции, полученный при создании счёта.
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": {
      "Id": 123456,
      "Amount": 1000,
      "Status": "Processed", // Возможные статусы: Processed (оплачен) | RemotePaymentCreated (выставлен) | RemotePaymentCanceled (отменен) | Expired (истек)
      "StatusDesc": "Оплачено",
      "OrderNumber": "ORDER-12345",
      "ClientMobile": "77071234567",
      "ReceiptUrl": "https://pay.kaspi.kz/receipt/..."
    }
  }
  ```

#### 3.4 Отменить выставленный счет

Позволяет кассиру отменить счет, если клиент передумал или долго не оплачивает.

- **Метод и путь**: `POST /api/invoice/cancel`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Тело запроса (JSON)**:
  ```json
  {
    "operationId": "123456" // Обязательно. ID операции в Kaspi
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": {
      "Status": "RemotePaymentCanceled",
      "StatusDesc": "Счет отменен"
    }
  }
  ```

#### 3.5 Получить историю удаленных счетов

Запрашивает список последних 20 выставленных удаленных счетов из истории Kaspi.

- **Метод и путь**: `POST /api/invoice/history`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Тело запроса (JSON)**:
  ```json
  {} // Можно отправлять пустое тело
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": [
      {
        "Id": 123456,
        "Amount": 1000,
        "Status": "Processed",
        "StatusDesc": "Оплачено",
        "CreatedDate": "2026-06-26T16:00:00"
      }
    ]
  }
  ```

### Группа 4: Оплата по QR-коду (QR Payments API)

Генерация и отображение динамического QR-кода на экранах кассы или POS-мониторах. Клиент сканирует код через приложение Kaspi.kz.

#### 4.1 Сгенерировать QR-код на оплату

Создает платежную QR-сессию и возвращает токен, по которому фронтенд должен отрендерить QR-код (например, библиотекой qrcode.js).

- **Метод и путь**: `POST /api/qr/create`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Тело запроса (JSON)**:
  ```json
  {
    "amount": 500, // Обязательно. Сумма к оплате в тенге
    "latitude": 43.238949, // Необязательно. Гео-координаты POS-терминала
    "longitude": 76.889709 // Необязательно
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": {
      "QrOperationId": 789012, // ID операции для опроса статуса
      "QrToken": "https://pay.kaspi.kz/pay/TokenSNString", // Ссылка для генерации QR-кода на фронтенде
      "ExpireDate": "2026-06-26T16:30:00.000Z", // Время жизни QR-кода
      "Amount": 500
    }
  }
  ```

#### 4.2 Проверить статус QR-платежа

Опрос статуса сканирования и оплаты QR-кода.

- **Метод и путь**: `GET /api/qr/status`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Параметры запроса (Query)**:
  - `qrOperationId` (string) — ID QR-сессии из шага создания.
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": {
      "Status": "Processed", // Возможные статусы: Processed (оплачен) | Wait (ожидание сканирования) | QrTokenCreated (создан) | CancelledByUser (отклонен клиентом) | Expired (истек)
      "StatusDesc": "Оплачено",
      "Amount": 500,
      "ReceiptUrl": "https://pay.kaspi.kz/receipt/..." // Чек об оплате
    }
  }
  ```

### Группа 5: История операций и Оформление возвратов (History & Refunds)

Низкоуровневые эндпоинты выписки и возвратов непосредственно по API Kaspi Pay.

#### 5.1 Получить историю операций торговой точки

Выгружает список транзакций за указанный день.

- **Метод и путь**: `POST /api/history/operations`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Тело запроса (JSON)**:
  ```json
  {
    "endDate": "2026-06-23", // Обязательно. Дата окончания выписки (YYYY-MM-DD)
    "lastTransactionDate": "", // Опционально. Используется для пагинации
    "statementPeriodCode": 0 // Опционально. Код смещения периода
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": [
      {
        "Id": 11223344,
        "Amount": 5000,
        "Type": "Sale", // Возможные типы: Sale | Refund
        "CreatedDate": "2026-06-23T11:45:00.000",
        "ConsumerName": "АЛИХАН Б.",
        "Status": "Confirmed"
      }
    ]
  }
  ```

#### 5.2 Получить детальную информацию по операции

Запрашивает детальную информацию по транзакции (включая размер комиссии Kaspi и чистую выручку).

- **Метод и путь**: `POST /api/history/details`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Тело запроса (JSON)**:
  ```json
  {
    "id": 11223344, // Обязательно. ID транзакции из истории
    "operationMethod": 0 // Опционально. По умолчанию 0
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": {
  ```

### Группа 6: Локальная база данных, Заказы и Аналитика (Orders & Stats)

Главные интеграционные эндпоинты для фронтенд-дашбордов и POS-касс. Работают с нашей PostgreSQL базой данных.

#### 6.1 Локальная проверка валидности сессии кассира

Активно проверяет связь между бэкендом и серверами Kaspi. Совершает тестовый запрос к Kaspi Pay. Если сессия протухла, возвращает `active: false`, сигнализируя кассиру о необходимости переавторизоваться.

- **Метод и путь**: `GET /api/session/check`
- **Заголовки**: `X-API-Key` (или сессионные заголовки).
- **Ответ (200 OK)**:
  ```json
  {
    "active": true
  }
  ```
- **Ответ при неактивной сессии (401 Unauthorized)**:
  ```json
  {
    "active": false,
    "error": "Session rejected by Kaspi API."
  }
  ```

#### 6.2 Создать заказ и выставить счет (Основной эндпоинт продаж)

Регистрирует заказ в нашей БД и одновременно выставляет удаленный счет покупателю в Kaspi.

- **Метод и путь**: `POST /api/orders/invoice`
- **Заголовки**: `X-API-Key`
- **Тело запроса (JSON)**:
  ```json
  {
    "orderId": "ticket_order_777", // Обязательно. Уникальный ID заказа в вашей кассовой системе
    "eventId": "event_kino_42", // Обязательно. Уникальный ID фильма/мероприятия
    "eventName": "Человек-паук: Нет пути домой", // Обязательно. Название для фискального чека
    "amount": 2500, // Обязательно. Сумма заказа в тенге
    "customerPhone": "77071234567", // Обязательно. Номер телефона клиента для счета
    "customerName": "Кирилл", // Опционально
    "customerEmail": "kirill@example.com" // Опционально
  }
  ```
- **🛡️ Защита от дубликатов**: Если этот эндпоинт вызывается повторно с теми же `orderId` и `X-API-Key`, бэкенд **не будет** создавать повторный счет в Kaspi. Он моментально вернет данные ранее созданного счета, предохраняя клиента от двойного списания.
- **Ответ (200 OK)**:
  ```json
  {
    "StatusCode": 0,
    "Data": {
      "Id": "kaspi_operation_uuid_777",
      "Status": "RemotePaymentCreated",
      "Amount": 2500,
      "ClientMobile": "77071234567",
      "OrderNumber": "ticket_order_777"
    }
  }
  ```

#### 6.3 Вручную переопределить статус заказа (Admin Status Override)

Используется администратором для принудительного закрытия зависших заказов (например, если клиент отменил заказ на кассе, или если клиент оплатил наличными при зависшем API). Это останавливает автоматический фоновый опрос этого заказа по API, обновляет статус в БД и **сразу отправляет соответствующий вебхук** (например, `payment.success` для `Processed`) вашему сайту.

- **Метод и путь**: `PATCH /api/orders/{id}/status`
- **Параметры пути**:
  - `id` (string) — Числовой ID записи в нашей БД (например, `"15"`) или строковый `orderId` вашей POS-системы (например, `"ticket_order_777"`).
- **Заголовки**: `X-API-Key`
- **Тело запроса (JSON)**:
  ```json
  {
    "status": "Processed", // Обязательно. Любой валидный статус оплаты (Processed | RemotePaymentCanceled | Expired)
    "status_desc": "Оплачено наличными администратору на входе" // Опционально. Комментарий
  }
  ```
- **Ответ (200 OK)**:
  ```json
  {
    "success": true,
    "message": "Order status manually updated to Processed."
  }
  ```

## 🚫 Стандартные структуры ответов с ошибками

Наш бэкенд возвращает стандартные HTTP-коды ошибок с унифицированным телом ответа. Всегда проверяйте поле `error` в корне JSON, если статус ответа отличен от `2xx`.

### Ошибка отсутствия авторизации (401 Unauthorized)

Отсутствует или не распознан заголовок `X-API-Key`, либо протухла сессия Kaspi.

```json
{
  "error": "Missing X-API-Key header."
}
```

### Ошибка нехватки прав или блокировки ключа (403 Forbidden)

Вы пытаетесь дернуть метод, доступ к которому отключен в правах API-ключа (например, выставление счетов запрещено), либо ключ организации заблокирован администратором.

```json
{
  "error": "Remote invoicing is not enabled for this API Key."
}
```

### Ошибка отсутствия связанной сессии Kaspi (403 Forbidden)

API-ключ активен, но кассир еще не прошел авторизацию на странице `/connect.html`.

```json
{
  "error": "Kaspi cashier account is not connected yet. Please complete OTP onboarding at /connect.html."
}
```

### Ошибка неверных параметров запроса (400 Bad Request)

Отсутствуют обязательные поля в JSON-теле или неверный формат параметров.

```json
{
  "error": "orderId, eventId, eventName, amount, and customerPhone are required."
}
```

### Внутренняя ошибка сервера (500 Internal Server Error)

Сбои в базе данных или непредвиденная ошибка на стороне API Kaspi.

```json
{
  "error": "Database connection error: Connection timeout"
}
```
